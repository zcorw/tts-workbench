# CMS 指定文章批量生成音频

在 CMS 的“内容”页勾选本页文章，然后选择“批量生成音频”。每批只处理明确选中的 1–20 篇文章，不会遍历或自动生成全部内容。原有批量分类、批量上线和单篇生成继续保留。

## 编辑稿与阅读库

批量生成使用服务端读取的**已保存编辑稿**。确认框显示所选正文版本、个人发音规则版本、原有音频及将使用的声音和语速；未保存的浏览器输入不会被当作已保存正文提交。

生成只更新编辑稿的当前音频，不发布文章，也不修改阅读库已上线的正文、分类或音频快照。已上线文章生成新音频后，仍须另外确认单篇或批量上线，阅读库才会切换到新发布版本。历史发布音频继续属于原发布快照。

## 确认与计费

- 默认跳过所有已有音频的文章，包括已经过期的音频。需要替换时，明确选择重新生成并确认；旧音频仅在新音频成功保存后被替换，失败时保留。
- 声音和语速没有独立的文章配置字段。已有音频可沿用其元数据中的参数；没有音频时，由确认界面明确选择可用声音与语速。需要生成但旧声音不再可用时，应重新明确选择，不会静默换成另一个供应商声音。
- 每篇使用确认的个人发音规则版本。排队期间正文、当前音频或规则发生变化时，会返回版本冲突，用户重新核对后再确认。
- 真正发起的语音请求按当前服务的既有计费和额度规则消耗额度。界面不提供未经确认的价格；取消不能撤回已经产生的请求或费用。

## 进度、取消与重试

批次和逐篇状态保存在共用 PostgreSQL 中，现有 Node 后端串行执行，不新增独立工作服务。页面显示服务端实际状态：排队、生成中、成功、失败、已跳过、已取消或结果不确定。页面导航或刷新后，从本人的任务接口恢复显示，隐藏页面暂停不必要的进度轮询。

任务区默认只显示紧凑的“已处理”进度条、数量和简短状态，失败及结果不确定的数量在收起时仍可见；进度条不代表全部生成成功。点击“查看详情”才展开逐篇结果、参数和最近任务。轮询、刷新状态或取消排队项不会强制展开详情，完成结果仍保留可查；刷新整个页面后默认收起。“停止未开始项”和失败项重新确认入口在收起时仍可操作。

同一账户最多一个活动批次。一次确认使用固定的 `requestId`：重复点击或相同请求重放返回原任务；同一标识配不同内容会冲突，已归档标识也不会重新收费生成。原单篇和批量生成共用账户的付费请求准入预算，队列等待不代表已经调用供应商。

“停止未开始项”仅取消仍在排队的文章；已经开始的项继续到实际结果。操作不会删除此前成功生成的音频。

失败项可以单独重试，但必须先加载该文章的最新保存版本，核对音频和规则，再确认一个新批次。成功、已跳过和已取消项不会被失败重试一起提交。不会自动刷新版本后收费生成，也不会自动合并冲突。

如果工作进程在请求期间中断，已经开始的项可能显示“结果不确定”。先检查已保存音频及阅读库状态，确认是否已有成功结果；不要把丢失响应当作生成失败并直接再次收费。未开始的队列项按服务端恢复状态继续处理。

## 接口与权限

API 版本为 1.5.0；[OpenAPI](openapi.yaml) 是请求与返回字段的唯一契约。

| 接口                                     | 用途                                   |
| ---------------------------------------- | -------------------------------------- |
| `POST /v1/cms/audio-batches`             | 创建或幂等恢复一个已确认批次，返回 202 |
| `GET /v1/cms/audio-batches`              | 最近五个本人批次，活动任务优先         |
| `GET /v1/cms/audio-batches/{id}`         | 查看本人批次实际状态                   |
| `POST /v1/cms/audio-batches/{id}/cancel` | 以空 JSON 对象停止未开始项             |

所有接口要求本人登录会话；写操作继续要求同源 Origin 与 CSRF。AI/RSS 只读凭证不能创建、取消或读取编辑侧音频任务。跨账户任务和文章标识不会授予读取或生成权限。任务记录不保存整篇正文或供应商凭据。

创建请求示例只包含虚构标识，不含正文和凭据：

```json
{
  "requestId": "10000000-0000-4000-8000-000000000001",
  "existingAudio": "skip",
  "items": [
    {
      "articleId": "20000000-0000-4000-8000-000000000001",
      "expectedRevision": 3,
      "expectedAudioId": null,
      "expectedRuleVersion": 2,
      "voice": "ja-jp-primary",
      "speed": 1
    }
  ]
}
```

常见冲突为 `AUDIO_BATCH_ACTIVE`、`AUDIO_BATCH_REQUEST_CONFLICT`、`AUDIO_BATCH_EXPIRED`、`REVISION_CONFLICT`、`ARTICLE_CONTENT_CHANGED`、`AUDIO_CHANGED` 或 `PRONUNCIATION_CHANGED`。逐篇 `WORKER_INTERRUPTED` 表示结果不确定；`CANCELLED_BEFORE_START` 表示未开始就取消。失败提示使用安全错误码，不回显供应商原始错误或密钥。

单篇音频请求保持兼容，新增可选 `expectedAudioId` 与 `expectedRuleVersion`，可在已有正文版本检查之外保护当前音频和个人规则版本。

## 运行与验收边界

服务端增加音频批次迁移文件。开发验收只能对新建隔离测试库执行迁移；本轮没有获准迁移或修改现有生产数据库。正式升级前应另行确认备份、迁移与应用更新步骤，不能仅替换前端产物就假定任务表已就绪。

测试应覆盖真实 HTTP/PostgreSQL 状态和模拟 TTS，包括重复请求、版本或音频冲突、旧音频保留、取消边界、中断不确定状态、仅失败重试、页面返回/刷新及原批量发布和固定音频播放。桌面及 320/390 手机宽度使用虚构数据验证。供应商网络、真实文章、真实密钥与付费语音不属于本轮验证范围；不据此声称已经生产上线或验证真实日文声音。
