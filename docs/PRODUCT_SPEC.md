## 2. 目标用户、角色与边界

- 访客：进入账户开通/登录流程，无合成和个人词汇读取权限。
- 已认证个人用户：读取自身资料，使用已授权音色，管理和试听自己的词汇，生成音频。
- 运维人员：配置供应商和应用环境，处理账户状态；首版不要求管理后台。
- NestJS 开发者：安装/引入账户模块，配置存储与认证策略，调用稳定公共接口。

账户模块拥有账户、凭据及认证生命周期，不认识 TTS 权限字符串或词汇表。应用拥有业务权限映射、个人作用域和词汇记录。TTS 拥有合成与能力校验，不查询账户或词汇 ORM 实体。个人作用域用于满足现有必填 tenantId，不代表首版有团队产品。

账户工程独立拥有package配置、构建、测试、文档、版本和产物；建议未来与TTS-gateway、tts-workbench位于D:/Workspace/github平级目录，拟名nest-account（名称待确认）。账户工程内部可以组织核心与存储适配器包，但不能以tts-workbench的packages子目录作为唯一工程边界。应用web/api是否workspace不受影响。

应用从明确版本的账户包和Gateway包接入，禁止兄弟仓库src内部路径引用。可用本地打包文件或私有registry，不强制公开npm发布；独立Git仓库和包分发是两件事。当前用户已授权在契约完成后创建独立账户工程并实施应用/Gateway 所需代码，前端 React 组件可先行；仍未授权新建 GitHub 仓库、提交/推送或远程部署。包与仓库边界继续约束实际实现。

最终交付由 Docker Compose 在 VPS 上运行，支持 GitHub Actions 远程部署；这两项均为用户确定的要求。独立账户和 Gateway 仍提供版本明确的包产物，由组合应用安装并构建为应用镜像。包分发 registry 与容器镜像 registry 分别配置；Compose 的具体服务划分由架构规划落实，不改变账户工程与 Gateway 的公共包边界。

外部访问由宿主机 Nginx 承担域名/TLS 和反向代理，前端、API 与音频在 Compose 内合流为一个入口。整个栈仅向宿主发布一个端口，必须显式绑定宿主 `127.0.0.1`；数据库、缓存等内部服务不设置宿主端口映射。不能以裸端口隐式绑定 `0.0.0.0`，也不能额外发布 IPv6 或容器 TLS 端口。

这里的 loopback 限制针对宿主发布地址，容器内部入口应按容器通信需要监听可达地址，例如 `0.0.0.0`，不能误配成只有容器自身可访问的 loopback。系统仍可提供公共网站，公网流量经宿主机 Nginx 进入，不直接访问 Docker 映射端口。

## 3. 词汇发音管理：确认范围与最小建议

本次用户澄清取代上一版“个人 alias 词典”的建议基线。术语统一为“词汇发音管理”；保留 DICT 编号仅用于任务追踪，不代表建设完整字典。释义、例句、词性、词条来源、查词服务及学习复习系统不在本次范围，也不再列作未决产品方向。

Q-01a/b和Q-08均已关闭。核心流程“输入文章→生成听音→正文选词→修改读法→保存个人规则→重新合成验证”。默认保存持久个人规则，当前同词其他出现及本人未来文章也受影响；面板清楚说明这个范围。独立词汇页只是辅助入口。默认个人操作不创建当前位置的局部标注。

可选“仅此处”是AI建议，用于同词在具体语境中的例外，用户主动选择后才创建局部位置标注，不写个人规则。局部标注优先于个人规则，其余正文使用本人规则；此时同词其他位置不受局部修改影响。global alias不能表达单次位置，新位置能力保留用于例外路径，不强加到默认持久操作。

本版本将“仅此处”及其位置编译器列为可选后续（T027/P2），不阻塞MVP。本文涉及局部范围/锚点/sub的细节均为启用该扩展时的条件设计；首版只需正文选词保存个人规则、派生标记和重新合成，不要求提供局部切换按钮。

建议首版以日文替代读法文本alias实现，例如目标词汇为日文汉字，读法可尝试假名；是否接受平假名/片假名及其实际发音效果需对选定日文音色验证，不能把用户“注音”理解为汉语拼音，也不承诺音高重音或IPA编辑。用户确认的是指定日文读法效果，alias是待验证实现建议。

**首版语言目标是ja-JP日文，不是中文先行再扩展日文。** 现有源码在快照类型、匹配器、SSML节点语言、配置、音色/供应商能力中绑定zh-CN；这是必须在后续实现阶段改造的集成缺口，不能成为产品仅支持中文的验收标准。首版必须具备日文音色/能力、ja-JP规则契约、日文正文规则应用和真实日文可听验收。不能只把快照language字符串改为ja-JP而保留中文音色与校验。

个人规则仍为一账户内部集合、保存事务更新及授权一致快照，无手动发布；首版有效规则和合成语言按日文契约对齐。不支持的具体音色/参数应拒绝并提示，不能悄悄按中文朗读或忽略日文规则。其他语言不阻塞当前日文MVP，扩展另议。

## 5. 页面、主要流程与异常状态

建议三个入口：账户页、语音工作台（含正文发音编辑主入口）、个人词汇规则页（辅助管理）。当前账户和退出放导航。选词编辑支持键盘和可访问操作，不以强制富文本技术实现；窄屏可完成流程。

账户页：选定标识与密码（若采用密码策略），提交、加载、失败、成功跳转。账户开通能力不等于已经决定公众自助注册；内部开通和公开注册由 Q-02 选择。

我的文章：列表展示标题、最后修改时间与音频状态，支持标题搜索、分页、新建、打开和删除。语音工作台增加标题编辑、显式保存和未保存状态；保存成功后才可基于该正文生成并保存音频。选词后就近显示原词、读法及“保存个人规则（应用当前同词及以后文章）”动作。个人规则保存与文章保存相互独立；标记可打开规则编辑，原字不改。详细导航、冲突及音频恢复行为见 [文章管理增量](ARTICLE_MANAGEMENT.md)。

主流程：登录→输入日文文章→选择日文音色生成听音→正文选日文词汇修改读法→默认保存个人规则→服务端确认→当前命中标记更新、音频标过期→重新合成验证→以后日文文章沿用。原文汉字不替换成假名读法。可选“仅此处”仍是后续例外，新规则不改变已读取快照的在途请求。

原文编辑：个人规则投影按新正文重新匹配，不维护持久位置，也不因文中删除某词而删除其个人规则。仅局部例外需要锚点维护：前方编辑可靠移位，后方不变，交叠/删词/整段替换标失效，不能猜移到另一处同词。失效局部标注须修复或删除后生成。个人规则标记消失不是局部失效。

音频一致性：文本、读法标注、音色、语速及已知个人规则变化后，旧音频仍可听但明确为旧结果。生成中发生修改，返回音频绑定提交时的状态，不能标为当前结果。重新生成成功后才更新当前播放器状态，失败保留旧结果标签，不自动付费重试。

个人规则页保留CRUD/试听；正文默认调用同一持久用例。已有同词规则时显示旧/新读法及当前、未来文章影响。持久保存成功前不显示已生效；失败保留输入表单和旧规则状态，可重试，不暗自转为局部保存。并发修改返回冲突并要求刷新，不覆盖他人窗口的新值。

建议首版不提供易误解的“一键撤销已保存”。“取消”只放弃未保存表单，浏览器文本撤销不撤销个人数据库规则。保存后修正通过再次编辑或“删除个人规则”；若后续增加撤销按钮，必须持久恢复前值或删除新建规则并进行版本冲突检查，失败不能假装回滚成功。

删除操作区分“删除个人规则（影响当前及以后文章所有命中）”与“删除仅此处标注”。前者成功后更新个人集合和正文投影，不删除另存的局部例外；后者只移除局部，若仍有个人规则则提示恢复个人读法。不能用通用“删除注音”同时混淆两个范围。

技术边界：默认正文操作复用个人CRUD和经过日文适配后的整段合成，不需/editor/speech或局部annotation；“复用”不代表当前中文硬编码直接可用，JPN-01为必要改造。若后续启用局部，T027需按届时日文音色sub/prosody支持验证；不能沿用中文能力推断已支持。用户不写XML/SSML。

## 6. 权限与数据生命周期

数据包含持久个人规则、每篇最新文章内容及唯一最后成功音频；正文上的词汇标记由个人规则派生，不保存为局部位置覆盖。Article保存最新title/text及revision/contentRevision；ArticleAudio与文章一对一，保存音频字节及生成所用正文版本、实际个人规则版本、音色和语速。不提供文章版本历史、音频历史、多读法局部标注或SSML手写。

通用身份转换为actorId、tenantId、排序去重permissions。普通合成/试听使用tts:voices:read、tts:synthesize、精确tts:voice:use:<alias>；应用规则另需tts:dictionary:use。宿主从可信身份取得本人内部集合ID，reader再校验所有权；客户端不能选择他人集合。无权/不存在记录错误不泄露存在性。

账户、个人规则及用户已保存的文章持久化，刷新或重新登录后可恢复；尚未保存的正文编辑仅在页面内存，离开前提示。每篇只保留最后成功音频，失败不能清除旧结果。删除文章不会删除个人规则；放弃正文编辑也不会撤销已保存读法。业务不提供历史版本，数据库备份仍按备份保留策略管理。正文、读法与原词不写日志，认证安全沿用。

词汇删除后的物理清理/备份过期、账户注销与凭据撤销政策需要Q-07明确。首版无账户注销页面不等于永久保留数据；上线前应有可执行处理流程。公开注册若启用，恢复、验证、防滥用和费用保护要求仍须确定。
