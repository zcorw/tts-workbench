以下各项已以最终 YAML 的操作、模型、描述和响应核查通过。描述性限制仍须在后端实现中执行，机器结构校验不替代运行时验证。

- 请求与响应字段、必填、可空、默认值、长度/数值限制、未知字段处理、示例和 operationId 清楚一致。
- 登录、注册、退出、会话过期、显示名称保存及注册关闭可由前端直接实现；不存在只有 UI 而无约定行为的必需动作。
- Cookie 安全属性与 CSRF 的取得/轮换/提交明确；账户不可见资源统一处理，客户端不得指定他人 owner、actor 或内部规则集合。
- 规则列表分页/搜索和完整正文投影需求兼容；跨页版本或一次全量读取有明确做法，不能只用列表当前页产生全文标记。
- 同词重复和版本冲突返回明确错误；更新与删除的前置版本传递方式确定；保存失败保留输入及旧状态，成功才刷新规则和音频状态。
- 日文音色能力与未配置状态明确；音色示例仅作字段说明，不冒充实际可用 voice。
- 正文合成和所需词汇试听共用已约定规则语义；原文不改、最左最长/单轮非递归、无本轮局部位置覆盖。
- 音频响应为可播放/下载二进制，明确媒体类型、文件名、请求 ID、实际采用的规则版本及完整性判断；错误不包装成伪音频，不自动付费重试。
- 401/403/404/409/413/415/429/依赖失败等与适用操作对应，错误结构和必要恢复信息一致；健康/readiness 不调用付费合成。
- OpenAPI 可解析、引用可解析且通过机器校验；前后端拥有同一版本与变更通知方式。
