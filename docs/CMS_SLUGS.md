# CMS 文章链接标识与创建恢复

## 普通编辑不需要填写链接标识

新文章的“高级设置”默认收起。日常填写标题、日文正文和需要的分类后即可保存，不必另外编写 slug，也不会把日文标题翻译成英文来生成链接。

链接标识与标题独立。省略 slug 或提交空白时，新文章使用 `article-` 加去掉连字符的文章 UUID 前 12 个小写十六进制字符作为稳定标识；遇到已有标识时依次尝试 `-2` 至 `-128` 后缀。标题以后改名，已分配的标识不会随之重算。

已有 CMS 文章提交空白或省略 slug 会保留原标识。原工作台文章若此前没有 CMS 元数据，第一次在 CMS 保存时才分配自动标识。保存空白不是清除现有链接的操作。

## 高级设置中的自定义标识

需要自定义时再展开高级设置。非空标识仍使用原规则：小写 ASCII 字母、数字，以单个连字符连接；去除首尾空白后校验。原始字段最多 120 个字符，不能用超长空白绕过限制。

- 合法示例：`interview-notes-1`。
- 非法格式返回 `400 INVALID_REQUEST`，不会悄悄替换为自动标识。
- 同一账户已有重名标识返回 `409 SLUG_CONFLICT`，保留输入，由用户调整。
- 自动候选耗尽返回 `409 SLUG_ALLOCATION_FAILED`，整次创建或更新事务回滚，不留下半篇文章。

更改的是编辑稿标识。既有发布快照、固定阅读库链接、RSS 和已发布音频不被静默改写；没有新增数据迁移或历史链接回填。

## 创建请求的幂等身份

API 版本为 1.6.0，仍有 56 个操作，没有新增路由。`POST /v1/cms/articles` 的 `requestId` 是可选 UUID，提供时直接作为新文章的 `article.id`。旧客户端省略该字段时保持原有创建方式。

同一账户在锁保护下，以同一身份重放相同的规范化标题、正文及全部可写 CMS 信息，且已存文章版本与 CMS 版本都为 `1`（初始创建状态）时，才返回已经创建的文章详情，不重复创建。标题按既有规则去除首尾空白，正文和摘要逐字保留；分类 UUID 转为小写，标签 UUID 转为小写并校验去重、排序。正文不会因链接生成而改写或翻译。

在上述初始状态下恢复时，省略或空白 slug 按该文章已保存的标识比较，不会重新分配；明确填写的自定义标识仍须与已保存值一致。规范化写入内容不同，或该 UUID 属于另一账户时，返回 `409 CREATE_REQUEST_CONFLICT`，不会当作覆盖更新。

任何后续版本演化都返回同一创建冲突，包括编辑、发布或字段修改后又还原；即使当前字段与原提交再次相等，也不自动认定为初次创建恢复。版本号与发布时间不由创建请求提交，服务端检查已存版本。此规则不需要新增持久请求哈希或迁移表。

这是一次创建的身份，不是文章标题，也不是 slug；不能把同一 `requestId` 用于另一篇新文章。正常编辑仍走带正文/CMS 版本检查的更新接口。

若创建请求的响应丢失，界面冻结当次请求身份和完整提交内容，提供显式恢复。恢复使用原身份及原内容，不自动换一个 UUID 再创建。创建冲突时保留本地输入，通过同一文章 ID 读取本人服务端文章，必须明确比较或载入最新内容，再决定后续编辑；不能把普通保存当作绕过创建冲突的捷径。

待确认请求仅保存在当前页面内存，不把私人正文或身份写入 `localStorage`。刷新、关闭页面或重启浏览器会丢失这份内存记录，无法保证自动找回原请求身份。若上次保存结果不确定，应先查看文章列表，确认是否已创建，再手工新建，避免重复内容。服务端文章与既有发布版本不会因浏览器内存丢失而删除。

## 导入和分类边界

本文的可选或空白 slug 只适用于普通文章创建、更新：

- 结构化导入仍要求合法且非空的 slug，继续按 `source` / `externalId` 去重和版本校验；没有改成自动补全或静默覆盖。
- 分类、标签的 slug 规则不变。
- 返回的 CMS 元数据仍包含实际保存的 slug；不会把写入时的可选字段扩散到阅读接口。
- 原有文章权限、CSRF、正文/CMS 并发冲突、音频、批量发布和批量生成流程保持原边界。

请求字段和响应以 [OpenAPI](openapi.yaml) 为准。本地验收使用虚构隔离数据和模拟 TTS，不代表已经迁移生产数据库、部署或验证真实语音供应商。
