## 3. 现有代码事实与初步取舍

| 事实 | 建议处理 | 原因 |
|---|---|---|
| Gateway 私有宿主包，没有正式库 exports，Nest 仅导出健康指标 | 规划库入口、应用服务与目录公共契约 | 直接引入必须成为真实可验证能力 |

| Gateway 必填 tenantId | 应用提供个人作用域映射 | 兼容契约但不强推团队产品 |

### v0.8 增量确认：单一宿主 loopback 端口与宿主机 Nginx

协调任务转来用户要求：“要求docker最终只提供一个127.0.0.1的端口访问，方便宿主机的nignx进行代理”。统一术语为宿主机 Nginx。约束适用于整个 Compose 栈：仅一个宿主发布端口，显式绑定 `127.0.0.1`；宿主机 Nginx 负责外部域名/TLS，反向代理到该端口，前端、API 和音频通过同一个应用内部入口提供。

数据库、缓存等仅通过内部容器网络访问，不额外映射宿主端口。禁止裸端口隐式绑定所有宿主地址，以及额外 IPv6 或容器 TLS 的宿主映射。绑定约束在宿主 Docker 发布地址，容器内部统一入口可按通信需要监听 `0.0.0.0`；不能将要求误解为只让容器内 Nginx 监听 loopback。公网网站仍由宿主机 Nginx 对外提供。

唯一端口的数值可配置且尚未指定，不需要为此再次澄清或阻塞规划；固定的是一个端口、宿主 `127.0.0.1` 绑定和宿主机代理位置。OPS-01/T023 增加单端口核验、外部不能直连 Docker 端口、经宿主 Nginx 可访问前端/API/音频的验收。后端维护 ARCHITECTURE/TODO，产品同步 README/PRODUCT_SPEC/本记录；继续保持 v0.8、19功能和30活动任务，仅做文档修订。
