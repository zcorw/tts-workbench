# 文章管理与最新音频

更新：2026-09-10。产品版本1.0，API1.1.0。状态：P0三方规划与契约已完成；F1文章管理已实现并通过前后端及产品验收；F2最新音频等待F1提交后实施。

## 需求与决定

用户明确提出：增加文章列表的一般增删改查，每篇只记录最后修改内容和最后生成音频；产品、后端、前端共同讨论决定修改方向；产品控制提交，每完成一个功能点commit，没有仓库自动创建。

三方决定：文章显式保存；只保留最新已保存标题正文和最后一次成功音频。生成失败保留旧音频，成功后原子替换。不会为保存或播放创建历史版本。未保存的输入是本地草稿，不得展示为已经保存。既有个人读法规则保持账户全局唯一，保存读法和保存文章是两个独立操作。

## 页面与用户操作

- “我的文章”：按最后修改时间倒序列出标题、修改时间、音频状态；支持标题搜索、分页、新建、打开、删除。无记录、无搜索结果、加载失败分别提示。
- 新建：标题去除首尾空白后1–120个Unicode码点，正文允许为空；创建成功后进入该文章。正文保留原字符，最多10000码点且49152 UTF-8字节，控制字符边界沿用现有契约。
- 编辑：可修改标题、正文并显式保存。只覆盖该文当前内容，没有版本历史。保存期间又有编辑时，响应只能确认已提交的那份内容，更新后的草稿继续显示未保存。
- 离开：有未保存修改时，内部导航、打开另一篇、新建和退出提供“保存并离开 / 放弃更改 / 继续编辑”。刷新或关闭用浏览器原生未保存提示。放弃文章编辑不撤销个人规则。
- 冲突：保存、删除带expectedRevision。409保留输入并提供重新载入最新版本的路径；重新载入须清楚说明会放弃当前草稿，不静默覆盖。
- 生成：正文非空。若有修改，先保存成功再生成；保存失败或保存期间再次编辑时停止本次生成，用户可继续编辑或重新发起。合成只使用服务器已保存的指定版本正文。
- 恢复：重新打开文章可播放、下载最后成功音频；从音频元数据恢复音色和语速，没有音频则使用当前可用默认值。音色暂不可用时仍允许播放已保存音频。
- 删除：确认后删除文章及其唯一音频；个人读法保留。删除失败或冲突不从列表假装移除，不自动重试写入。

## 唯一音频与并发语义

Article.revision用于标题/正文编辑与删除的条件写；contentRevision仅在正文实际变化时递增，单改标题不会使音频过期。音频记录包含audioId、contentRevision、实际ruleVersion、voice、speed、生成时间和字节数；正文、规则版本或当前音色语速不一致时显示“需重新生成”，旧音频仍可播放下载。

每次生成分配单调序号，供应商调用在数据库事务之外，完整音频最多8MiB。完成阶段重新验证账户有效、文章归属与存在、正文版本未变，再以短事务替换唯一音频。先发A、后发B：B先成功时A晚到不能覆盖；B失败而A成功且正文仍匹配时A可保存。正文已保存为新内容则旧请求不能写入；规则在途变化可以保留实际快照版本并显示过期。

删除文章后在途请求不能重新创建文章或音频。前端以账户、articleId和本地编辑代次隔离迟到响应；离开页面不声称服务端已取消，重新打开以服务端状态为准。

GET音频必须同时指定文章ID和当前audioId，且检查本人归属；被替换的audioId、他人资源或不存在统一404。客户端仅刷新元数据并至多取一次新ID，不无限重试，也不自动重新计费合成。所有生成入口复用既有账户付费限流、CSRF、取消与错误处理。

## 存储和范围

三方技术决定：继续使用PostgreSQL，文章一条记录保存最新文本，独立音频表以article_id为唯一主键/外键并级联删除，bytea与元数据一起事务替换。列表只查询元数据，不能加载所有音频字节。账户库及Gateway无需增加文章业务。

团队工程默认：每账户最多100篇文章，可通过部署配置调整，config返回实际上限；满额创建返回ARTICLE_LIMIT，删除释放名额。单份音频8MiB不变，默认最多约800MiB当前音频/账户，不新增计费或配额管理页面。备份、WAL和物理页清理沿用数据库策略；“只保留最新”指业务记录，不承诺备份中的旧字节立即消失。

新内容仅本人可查改删与下载，不新增分享、文件导入、协作、多版本历史、自动保存、回收站或远程部署。单词候选试听及个人规则试听继续使用既有临时接口，不写入文章音频。
