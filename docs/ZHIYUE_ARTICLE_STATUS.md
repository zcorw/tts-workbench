# 知阅文章状态筛选 · 2026-11-16

用户确认增加“已发布 / 草稿 / 全部”，默认已发布。本次功能随两个项目各自的功能分支提交并推送；未部署或签发凭据。

## 行为与边界

- 专用设备本人只读接口支持 status=published|draft|all，默认 published 保持原发布快照。
- draft 表示没有当前发布版本，包括撤稿文章，读取最新已保存正文、当前分类和最后成功音频；不读取浏览器未保存编辑。
- all 将当前发布和未发布草稿合并，每篇文章一次。已发布但编辑未重新发布的文章仍显示发布快照。
- 分类/关键词、总数、分页及语义分类映射均保持状态范围。按发布或草稿保存时间倒序、草稿/全部按文章 ID 倒序打破同时间排序，默认已发布保持原发布版本顺序；跨请求内容变动可重新加载。
- 设备授权限定当前账号；不扩展普通 CMS 发布阅读令牌，不增加写入、合成或管理员能力。

## 契约与迁移

OpenAPI 1.10.0 共83个操作，生成类型和指纹已同步。

GET /v1/zhiyue/read/articles、GET /read/articles/:id 支持 status 查询；POST /read/search 接收可选 status，返回 filters.status 供后续分页复用。status 由客户端明确选择，不交给模型决定。列表/详情增加 status、updatedAt，草稿 publishedAt=null。已发布读取冻结分类，草稿读取当前已保存分类，列表不返回正文和音频字节。

草稿详情 contentVersion 是正文版本句柄，releaseId 是音频 UUID（有音频时）或无音频草稿句柄。POST /read/drafts/:id/audio-ticket 接收精确 audioId；媒体票使用既有设备存活、短时效、字节范围及大小限制，增加文章和音频版本来源。每次媒体读取都检查账号、文章仍为草稿以及音频 ID 一致；替换、删除、发布状态和解绑后旧来源不可读。不调用音频合成，最后成功音频可能像 CMS 一样落后于最新正文。

先按正常发布流程执行新增1794873600000-zhiyue-draft-media迁移，再更新 API 和知阅 aiui 源码包。默认已发布接口继续兼容旧眼镜客户端。知阅源码包为相邻项目 artifacts/zhiyue-article-status-20261116.zip。
